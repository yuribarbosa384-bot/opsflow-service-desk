# Revisão técnica inicial — setembro de 2026

## Decisão

Manter como estudo demonstrativo com apoio de IA, não como produto pronto para operações reais. Não há justificativa técnica nesta revisão para exclusão definitiva. A adequação como estudo não certifica o domínio pessoal do autor.

## Correções verificadas

| Constatação | Evidência | Tratamento |
| --- | --- | --- |
| API descrita como local sem endereço de escuta explícito | `apps/api/src/server.ts`, `app.listen` | Padrão alterado para loopback; configuração explícita preservada para container |
| Origem irrestrita nas rotas | `apps/api/src/app.ts`, `createApp` | Origens externas rejeitadas antes dos handlers; testes de leitura, exclusão e preflight |
| Guia sugeria API pública e túnel sem controle de acesso | `docs/DEPLOYMENT_GUIDE.md` | Retiradas orientações de exposição; Docker com porta publicada somente no loopback |
| Dependências com alertas conhecidos | Consulta `npm audit` antes da atualização: 8 pacotes reportados, sendo 6 com classificação alta | Atualizações compatíveis no lockfile; consulta posterior com zero alertas |

Zero alertas de dependências não equivale a ausência de vulnerabilidades. A classificação dos pacotes não prova exploração no contexto do projeto.

## Limites ainda presentes

- Não há autenticação ou autorização no `createApp`. Origem e endereço de escuta não substituem identidade e permissões. Clientes locais sem Origin continuam permitidos.
- `createTicketEvent` usa nome fixo como ator padrão e o endpoint de comentários aceita ator informado. O histórico é demonstrativo, não uma auditoria de identidade confiável.
- Alteração de tarefas e inclusão de eventos são chamadas separadas (`replaceAll` e `appendEvent`). Uma falha entre ambas pode deixar tarefa alterada sem evento correspondente.
- O repositório salva o conjunto inteiro de tarefas. O risco de perda de atualizações com múltiplos escritores precisa de teste específico; não foi reproduzido nesta etapa.
- `seedIfEmpty` usa contagem de tarefas como condição. O comportamento após excluir todas e reiniciar requer correção e teste de regressão antes de uso persistente real.

## Verificação executada

Testes de domínio (7), API (10) e formulário (1) passaram. Os testes da API e do formulário foram repetidos após atualizar dependências. Typecheck e build passaram. Docker, testes E2E e exposição de uma instalação real não foram testados. Nenhuma ação foi executada contra dados de produção.

## Escopo

Esta é uma primeira revisão do OpsFlow, não uma auditoria completa de todos os repositórios, do histórico Git ou de todas as regras de negócio.
